# The Debian package (LCOS, Devuan, Debian)

`build-deb.sh` produces `chonkstep_<version>-<revision>_<arch>.deb`: the
X11 session, and only the X11 session.

The target this exists for is [LCOS](https://github.com/BryanLunduke/LCOS),
which is Devuan Excalibur -- Debian 13 "trixie" with systemd removed --
running the XLibre X server. The package is plain Debian, so it installs
on Debian and Devuan too.

## What is in it, and what is deliberately not

| Shipped | Left out | Why |
| --- | --- | --- |
| `/usr/bin/chonkstep` | `chonkstep-wayland` | The Wayland session wants DRM, libinput and libseat. LCOS has no logind and no seat manager. |
| `chonk-about`, `chonk-netjoin`, `chonk-get`, `chonkstep-bugreport` | `omarchy-export-themes`, `omarchy-install-desktop-chonkstep` | There is no Omarchy here to export to. |
| `/usr/lib/chonkstep/xsession.sh` and the reload/restart/verify helpers | `wayland-session.sh`, `chonkstep-session` | Same as above. |
| `/usr/share/xsessions/chonkstep.desktop` | the SDDM theme, the uwsm session entries | LCOS's display manager is LightDM. |
| the X11-relevant docs | portal, screen-sharing, Wayland and Omarchy docs | Shipping them would promise features this package does not have. |

That narrowness is the whole design. Supporting LCOS costs one
`cargo build -p chonkstep` and inherits every fix the Omarchy work makes
to the shared `chonk-shell`; it does not add a second desktop to keep
alive.

## Dependencies

The control file's `Depends` is generated by `dpkg-shlibdeps`, and comes
out remarkably short:

    Depends: libc6 (>= 2.39), libgcc-s1 (>= 4.2), dbus

`wm-x11` speaks the X protocol through `x11rb`, which is pure Rust, so
the binary links no libX11 and no libxcb -- only libc, libm and libgcc.
`dbus` is a real dependency because `xsession.sh` execs the window
manager through `dbus-run-session`.

There is deliberately **no dependency on an X server**. Debian's own
window managers (openbox, i3-wm, fluxbox) depend on libraries only, and
following that convention is what lets this package install on LCOS at
all: LCOS has no `xserver-xorg-core`. Its XLibre packages provide the
virtual `x-window-system-core` and `xorg` under entirely different
package names (`xserver-xlibre-core` and friends), and a window manager
can in any case be pointed at a display it did not start.

## Building

Build in a container whose libc matches the target. LCOS 0.3 and
`debian:trixie` are both glibc 2.41; building against the newer glibc on
a current Ubuntu would produce a package that installs and then refuses
to start.

    docker run --rm --platform linux/amd64 \
      -v "$PWD":/src -w /src rust:trixie \
      bash -c 'apt-get update -qq && apt-get install -y -qq dpkg-dev && packaging/debian/build-deb.sh'

The result lands in `dist/`. `DEB_REVISION` overrides the packaging
revision; the upstream version always comes from the workspace
`Cargo.toml`, so it can never disagree with the Arch package about what
a given version is.

## Installing on LCOS

    sudo apt install ./chonkstep_0.3.0-1_amd64.deb

The session then appears in LightDM's session picker as "chonkstep".
To make it the autologin session instead of picking it by hand:

    sudo sed -i 's/^user-session=.*/user-session=chonkstep/' /etc/lightdm/lightdm.conf
    sudo service lightdm restart

`picom` is a `Recommends` rather than a `Depends`: it gives the theme's
translucent terminals, and `xsession.sh` starts it only if it is
present, so the desktop is fully functional without it.

## CI

`.github/workflows/lcos-package.yml` builds this on every pull request
and on `preview-v*` tags, and on tags attaches the `.deb` to the release
`github-release.yml` created. It is a separate workflow on purpose: the
Arch packages are the Omarchy deliverable, and nothing here may hold
them up or fail their workflow.

Each build is verified by installing the package into a bare
`debian:trixie-slim` image and running it. That is the only test that
actually proves `Depends` is complete -- a runner with a desktop already
on it would pass with a short dependency line and ship a package that
fails at someone's login screen.
