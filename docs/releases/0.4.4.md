# ChonkStep 0.4.4 alpha

ChonkStep 0.4.4 adds an LCOS X11 package and fixes window resizing, logout,
monitor configuration, client isolation, and unnecessary background work.
It remains an alpha release, published under the `preview-v0.4.4` tag.

## Desktop and compositor fixes

- Client-decorated Wayland applications retain their toolkit input regions,
  including resize handles outside the window geometry. Resize grabs preserve
  the pointer's starting offset at 1x, 1.5x, and 2x display scales.
- Logout signals remain deliverable in launched applications. Nested hot
  restart reconnects to the original host display instead of its own old socket.
- Lua `hl.monitor({ transform = N, ... })` uses the same representation as
  classic monitor configuration. Rejected monitor scales still reserve the
  output's original layout slot, preventing the next automatic output from
  overlapping it.
- Clients admitted through `wp_security_context_v1` cannot discover or bind
  privileged capture, clipboard-control, virtual-input, layer-shell, and related
  globals. Ordinary desktop clients retain their existing access.
- Frame callbacks, presentation feedback, and FIFO barriers follow actual visible
  surfaces, including overflow subsurfaces. Hidden animation clients sleep until
  they become visible again.
- Appearance propagation uses one worker, keeps only the latest pending change,
  and bounds subprocess execution. Config polling reuses stored paths. X11
  property reads are capped at 64 KiB, with oversized identities and capability
  lists rejected rather than partially interpreted.

The audit's three paired release measurements reduced hidden redraws from 120
to zero and median dispatch passes from 383 to 260 for the same 120 visible
frames. A 256-file config fixture reduced allocation requests from 5,240 to zero
over 20 unchanged polls. Idle CPU and memory samples overlapped; no improvement
in those metrics or native hardware latency is established. See the
[review report](../engineering/2026-09-08-adversarial-review.md) and its raw
measurements for scope and reproduction.

## LCOS package

LCOS-specific artwork and themes are enabled only for the LCOS package. The
default Arch package retains its existing assets.

LCOS is amd64-only Devuan Excalibur: Debian 13, sysvinit, LightDM, XLibre.
ChonkStep's X11 backend already ran there unmodified, because `wm-x11` speaks
the protocol through pure-Rust `x11rb` and links neither libX11 nor libxcb. The
new Debian package therefore declares `libc6`, `libgcc-s1`, `dbus` and
`x-terminal-emulator` and nothing else, and deliberately does not depend on an
X server at all — Debian's own window managers depend on libraries only, which
is what lets the same package install on LCOS, where `xserver-xorg-core` does
not exist and XLibre provides the virtual packages under different names.

Everything LCOS-specific sits behind an `lcos` Cargo feature that is off by
default, so `include_bytes!` behind a `cfg` leaves nothing in the Arch package.
During LCOS bring-up, stripped binaries measured 26,996,816 bytes by default against 29,666,504
with the feature, a difference of 2,669,688 bytes, and no LCOS string appears
in the default build at all.

Four themes ship with it. The LCOS theme's palette is sampled from LCOS's own
boot splash, which is `#081830` across 95.8% of the frame inked in `#F8F8F8`.
Three Lunduke desk themes are sampled from the photographs LCOS installs, and
each prefers its own photograph when the host has it — resolved when the theme
is applied rather than named in the theme's `wallpaper` field, because
`omarchy-export-themes` must resolve and render a theme's declared wallpaper and
fails on one that exists only on another machine. The `lunduke-navy` artwork and
the LCOS dock mark are original to this project; LCOS's own logo is a three-line
wordmark whose third line is sub-pixel in a 56px tile, and embedding a copy of
somebody else's mark is a licensing question this repository already records for
the Omarchy-derived grounds.

The shared text and desktop-mark improvements also apply to every theme.

Glyph pen positions are now snapped to whole pixels. cosmic-text bins the
fractional part of a pen position into the glyph cache key, so the same
character rasterises differently depending on where in a string it lands: the
word "Lavender" measured 56px wide in one menu row and 55px in another, the two
bitmaps differing by 4.6% of full ink coverage. That is correct behaviour and
buys evenly tracked words, but at the 12px this chrome is set in a stem is
barely wider than a pixel.

The dock mark is resampled with Lanczos3 to the size it is drawn at and blitted
1:1. Drawing a 256px mark into a 44px tile is a 5.8x reduction, and
`FilterQuality::Bicubic` is a four-tap filter with no mipmapping behind it, so
the disc edge came out hard and stair-stepped.

## Validation

- The earlier LCOS bring-up was verified on LCOS 0.4 under KVM on an i9-9900K:
  installed from the `.deb`, selected through LightDM, themes applied from the
  root menu, and each desk theme confirmed to bring its photograph with it.
- A CI job asserts the feature split in both directions: an LCOS marker leaking
  into the default build fails, and a marker missing from the `--features lcos`
  build fails, so the check cannot pass by building nothing.
- The `.deb` is built in a `debian:trixie` container matching the target's
  glibc exactly, then installed into a bare `debian:trixie-slim` image and run,
  which is the only test that proves `Depends` is complete.
- Release qualification includes strict workspace Clippy and Rustdoc, Rust and
  Python checks, SDK checks, the Xvfb regressions, and the nested Wayland suite.
  The audit checkpoint passed 2,057 Rust tests including doctests and 271 nested
  integration cases, with no missing-client skips in the nested suite. Monitor
  regressions additionally compare both config parsers and malformed scale cases.
- Both native Arch packages and their debug-symbol packages are built,
  inspected, and attested by the release workflow. LCOS publication requires
  its recipe lint, feature-separation check, and package install check to pass.

## Earlier LCOS bring-up measurements

These measurements were recorded during the initial LCOS work, before the
compositor audit fixes. They are not measurements of the final release package.

Same VM, same 1920x1200, same settle time, medians of repeated samples:

| | LCOS stock (XFCE) | ChonkStep |
| --- | --- | --- |
| Idle CPU | 4.8% | 0.5% |
| System memory used | 559 MiB | 412 MiB |
| Desktop process RSS | 497 MiB | 45 MiB |
| Time to interactive | 0.90 s | 0.59 s |
| Terminal launch | 80 ms | 61 ms |
| Processes | 174 | 162 |

Memory used is `MemTotal - MemAvailable`, which is what the session costs the
machine. Summed RSS double-counts shared libraries and is reported for detail
rather than as the headline.

## Installing on LCOS

Download the amd64 package and its checksum from the
[0.4.4 release](https://github.com/iconidentify/chonkstep/releases/tag/preview-v0.4.4):

```sh
chonkstep_dir="$(mktemp -d)"
chonkstep_deb="chonkstep_0.4.4-1_amd64.deb"
curl -fL -o "$chonkstep_dir/$chonkstep_deb" \
  "https://github.com/iconidentify/chonkstep/releases/download/preview-v0.4.4/$chonkstep_deb"
curl -fL -o "$chonkstep_dir/$chonkstep_deb.sha256" \
  "https://github.com/iconidentify/chonkstep/releases/download/preview-v0.4.4/$chonkstep_deb.sha256"
(cd "$chonkstep_dir" && sha256sum --check "$chonkstep_deb.sha256")
sudo apt install "$chonkstep_dir/$chonkstep_deb"
```

Select **chonkstep** in LightDM for the next login. The package carries GitHub
build provenance; verify it with
`gh attestation verify "$chonkstep_dir/$chonkstep_deb" --repo iconidentify/chonkstep --signer-workflow iconidentify/chonkstep/.github/workflows/lcos-package.yml`.

For Omarchy or other Arch systems, use the native `x86_64` or `aarch64`
packages and matching debug symbols from the same release. See the
[Arch installation instructions](../../README.md#installing-on-omarchy-or-any-arch).

## Known limitations

- Native DRM rotation direction, mixed-refresh displays, hotplug, VT switching,
  and GPU-reset recovery still require hardware qualification. The monitor
  parser fix does not close [the rotation-direction investigation](https://github.com/iconidentify/chonkstep/issues/144).
- Security contexts depend on the surrounding sandbox preventing access to the
  unrestricted display socket; they do not sandbox ordinary desktop clients.
- Nested restart requires a reconnectable host display address; an inherited
  display FD alone is outside the verified restart contract.
- The dependency audit reports no vulnerability-category findings, but retains
  three warnings for unmaintained `cgmath`/`ttf-parser` and the `cgmath`
  `swap_columns` advisory. The audited project code does not call that method.
- The LCOS package ships the X11 session only. The Wayland compositor wants DRM,
  libinput and libseat, and LCOS has no logind and no seat manager.
- Theme-to-photograph pairing depends on the host shipping the pictures under
  `/usr/share/backgrounds/<ID>`; elsewhere each theme falls back to the solid
  ground it names.
- The Debian package is amd64 only, because LCOS is: every LCOS release to
  date is a single amd64 ISO.
- The Debian package is not in any apt repository. It is a release asset.
