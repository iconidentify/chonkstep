# ChonkStep 0.6.1

Window management, monitor handling, capture privacy and Omarchy configuration
improvements since 0.6.0. Published through the `preview-v0.6.1` prerelease
channel, including the changes merged in PRs #296–#299 and their review fixes.

## Highlights

- **Layouts and scratchpads:** Omarchy's default and per-workspace layouts,
  window-rule size and position expressions, named special workspaces, monitor
  focus and workspace moves, and previous/occupied workspace selectors.
- **Fullscreen and presentation:** client-only fullscreen keeps a window in
  its tile while telling the application it is fullscreen. Motion can be
  switched off, and window opacity, inactive dimming and the transparency
  toggle follow configuration and IPC requests.
- **Outputs:** disable and re-enable monitors, preserve unrelated runtime
  monitor settings during reload, retain parked connectors after failed
  probes, skip non-desktop connectors during hotplug, and retry failed links.
- **Capture privacy:** `no_screen_share` windows are redacted from
  compositor-rendered captures. Their switcher previews use icons, and their
  drag icons remain visible on the display while being omitted from captures.
- **Input and activation:** a shortcut-inhibition escape chord suspends each
  window independently. Activation tokens must carry valid focus and input
  provenance. Drag icons follow the correct mouse or touch input, including
  when both are held at once, and disappear on drop or lock.
- **Configuration and IPC:** one dispatcher vocabulary for bindings and IPC,
  window selectors that preserve spaces and commas, per-item configuration
  diagnostics, honest rejected-reload reports, and effective keyboard modes
  retained after invalid mode edits. Toplevel tags and descriptions are
  exposed, including `match:xdg_tag` rules.
- **Upgrade and application handling:** Omarchy's reload pause covers both
  configuration and theme following. Application entries refresh off-thread
  as packages come and go; stale menu picks are rejected and named pipes
  cannot stall the scanner. Control-socket request and connection budgets
  keep a flooding client from monopolizing a servicing pass.

## Validation and limits

The merged changes passed the full CI suites, including nested Wayland tests,
X11 smoke checks, workspace lint and documentation checks, dependency auditing
and package verification. Regression coverage includes private capture paths,
mixed mouse/touch drags, activation serials, independent shortcut suspensions,
selector parsing, reload guards, application scanning and socket flooding.
The release workflow validates the exact release revision and verifies native
package identities and GitHub build provenance before publishing.

Physical DRM output disable/re-enable, display-link recovery and headset
connector handling need hardware testing beyond the nested compositor suites.
Mirroring and a second DRM device remain unsupported. Omarchy's clamshell,
internal-monitor and monitor-watch scripts remain unbound pending their request
fixtures. Animated cursor shapes still use their first frame. One local
`uwsm` activation integration case could not run without a systemd user manager;
the direct activation regressions passed.

The Debian/LCOS package contains the X11 session. Wayland protocols, capture
privacy rules, drag icons, Spaces and Hyprland IPC compatibility require the
native Arch Wayland package. Install the new binaries, then log out and back
in to use them; a configuration reload does not replace the running compositor.

## Installing on Arch or Omarchy

Download the package for your architecture and verify its checksum:

```sh
chonkstep_dir="$(mktemp -d)"
chonkstep_arch="$(uname -m)"
chonkstep_pkg="chonkstep-0.6.1-1-$chonkstep_arch.pkg.tar.zst"
curl -fL -o "$chonkstep_dir/$chonkstep_pkg" \
  "https://github.com/iconidentify/chonkstep/releases/download/preview-v0.6.1/$chonkstep_pkg"
curl -fL -o "$chonkstep_dir/SHA256SUMS" \
  "https://github.com/iconidentify/chonkstep/releases/download/preview-v0.6.1/SHA256SUMS"
(cd "$chonkstep_dir" && sha256sum --ignore-missing --check SHA256SUMS)
sudo pacman -U "$chonkstep_dir/$chonkstep_pkg"
omarchy install desktop-chonkstep
```

Both `x86_64` and `aarch64` packages have matching `chonkstep-debug-0.6.1-1-`
packages for crash reports. Verify native package provenance with:

```sh
gh attestation verify "$chonkstep_dir/$chonkstep_pkg" \
  --repo iconidentify/chonkstep \
  --signer-workflow iconidentify/chonkstep/.github/workflows/package.yml
```

## Installing on LCOS

Download the amd64 X11 package and its checksum from the
[0.6.1 release](https://github.com/iconidentify/chonkstep/releases/tag/preview-v0.6.1):

```sh
chonkstep_dir="$(mktemp -d)"
chonkstep_deb="chonkstep_0.6.1-1_amd64.deb"
curl -fL -o "$chonkstep_dir/$chonkstep_deb" \
  "https://github.com/iconidentify/chonkstep/releases/download/preview-v0.6.1/$chonkstep_deb"
curl -fL -o "$chonkstep_dir/$chonkstep_deb.sha256" \
  "https://github.com/iconidentify/chonkstep/releases/download/preview-v0.6.1/$chonkstep_deb.sha256"
(cd "$chonkstep_dir" && sha256sum --check "$chonkstep_deb.sha256")
sudo apt install "$chonkstep_dir/$chonkstep_deb"
```

Select **chonkstep** in LightDM for the next login. Verify package provenance
with:

```sh
gh attestation verify "$chonkstep_dir/$chonkstep_deb" \
  --repo iconidentify/chonkstep \
  --signer-workflow iconidentify/chonkstep/.github/workflows/lcos-package.yml
```
