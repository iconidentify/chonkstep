# ChonkStep 0.6.0

Omarchy-first integration, System 7 and modern themes, frames for client-drawn
apps, and fixes across input, capture and monitor hotplug. Published through the
`preview-v0.6.0` prerelease channel.

- **Omarchy-first desktop:** the built-in dock, instruments and persistent
  workspace switcher are gone from both sessions, and Omarchy's bar supplies
  them. ChonkStep Help documents the session's own shortcuts, the root menu
  names Omarchy, and an Omarchy bar plugin shows agent sessions.
- **Hyprland IPC and Lua compatibility:** every SUPER+K keybindings-menu row
  replays; `hl.monitor` applies mode and position; Omarchy's pop-out, width,
  close-all and scaling scripts run; the twelve keyboard resize chords bind;
  `suppress_event` and `idle_inhibit` rules apply; IPC geometry is logical.
  The Lua reader evaluates conditions and locals, stops at bounded limits, and
  takes the keyboard layout from `/etc/vconsole.conf`.
- **Laptop and input devices:** the lid switch runs Omarchy's lock handler;
  touchpad toggles and per-device rules work by name; mouse and touchpad
  scrolling are configured separately; Num Lock and the remaining touchpad
  settings apply.
- **Pointer:** the pointer hides while typing or idle, client-named cursor
  shapes come from the Xcursor theme, scripted pointer warps are served, and
  browser clicks land on the right pixel after a fullscreen or resize.
- **Window decorations and themes:** Obsidian, Washi and Relay; the System 7
  decoration style with three System 7 picker themes; menus, switcher and
  Overview captions in the selected style; ChonkStep resize frames for GTK4
  and libadwaita apps that draw their own header bar.
- **Window management:** Spaces no longer depend on the Mac keyboard profile,
  now experimental and off by default. Overview defaults to the classic
  arrangement, leaves minimized windows out and keeps shaded windows rolled
  up. Activation switches to the window's workspace, and a client's early
  fullscreen or maximize request applies at map.
- **Capture and recording:** capture shortcuts work over menus, Help and
  Overview; recording works at fractional scales; window captures are no
  longer shifted by client shadows; `chonkrec --demo` records the capture
  controls.
- **Security:** the ext window list and workspace manager are hidden from
  sandboxed clients, a malformed IPC request can no longer panic the session,
  and Lua `exec_cmd` strings are read as literals.
- **Hardware and display robustness:** lock surfaces survive an unplugged
  output; gamma, color-transform and DPMS ownership survive hotplug; scale
  changes and hotplug use the running configuration; lock surfaces fit
  fractional-scale outputs.

## Changes to existing setups

- The dock, dock applets and their SDKs are removed on Wayland and X11.
- Mac keys need `keyboard_mode = "mac"`. The legacy `interaction_mode = "mac"`
  still implies them while `keyboard_mode` is unset.
- Overview excludes minimized windows. Restore them from their desktop preview
  tiles, now on by default (`minimized_previews`), or from the window switcher.
- Bound resize steps, including `grow-width` and `shrink-width`, are logical
  pixels.
- `natural_scroll` and `scroll_factor` under `[input]` configure mice;
  touchpads read `[input.touchpad]`.
- GTK4 and libadwaita apps that draw their own header bar now get a ChonkStep
  frame; list an app in `[decorations] client_side` to keep it bare.

## Client-drawn application frames

Apps such as Files and Pinta keep their own header bar and gain ChonkStep's
themed borders and resize edges. They are told they are tiled, so they drop
their invisible shadow. When the session starts, a GTK button layout still at
its stock `appmenu:close` becomes `appmenu:minimize,maximize,close`, so header
bars show every button the compositor honors; a layout you set yourself is
never changed. To put the full ChonkStep titlebar above such apps as well, set:

```toml
[decorations]
frame_client_drawn = true
```

The app still draws its own header bar beneath it. A reload applies the change
to open windows, and `[decorations] client_side = ["app-id"]` keeps one app
bare.

## Limits

Hyprland IPC still refuses disabling and mirroring an output. Omarchy's
laptop-display, clamshell, monitor-watch and mirroring scripts therefore stay
unbound. A window that asks for fullscreen before it maps is told so one
configure after mapping, so it can draw one windowed frame. Animated cursor
shapes show their first frame. Three-finger drag needs a newer libinput.
GTK apps running through XWayland keep their stock window buttons. Nested
tests cover protocol, input and pixels, not every real connector's mode set.

The release review is in
[the review report](../engineering/2026-09-14-release-review.md).

## Installing on LCOS

Download the amd64 package and its checksum from the
[0.6.0 release](https://github.com/iconidentify/chonkstep/releases/tag/preview-v0.6.0):

```sh
chonkstep_dir="$(mktemp -d)"
chonkstep_deb="chonkstep_0.6.0-1_amd64.deb"
curl -fL -o "$chonkstep_dir/$chonkstep_deb" \
  "https://github.com/iconidentify/chonkstep/releases/download/preview-v0.6.0/$chonkstep_deb"
curl -fL -o "$chonkstep_dir/$chonkstep_deb.sha256" \
  "https://github.com/iconidentify/chonkstep/releases/download/preview-v0.6.0/$chonkstep_deb.sha256"
(cd "$chonkstep_dir" && sha256sum --check "$chonkstep_deb.sha256")
sudo apt install "$chonkstep_dir/$chonkstep_deb"
```

Select **chonkstep** in LightDM for the next login. The package carries GitHub
build provenance; verify it with
`gh attestation verify "$chonkstep_dir/$chonkstep_deb" --repo iconidentify/chonkstep --signer-workflow iconidentify/chonkstep/.github/workflows/lcos-package.yml`.

For Omarchy or other Arch systems, use the native `x86_64` or `aarch64`
packages and matching debug symbols from the same release. See the
[Arch installation instructions](../../README.md#installing-on-omarchy-or-any-arch).

The LCOS package contains the X11 session, which in this release also loses the
built-in dock. The System 7 decoration style works there too. Spaces, the Mac
keyboard profile, capture controls and Hyprland IPC compatibility require the
Wayland compositor in the native Arch packages.
