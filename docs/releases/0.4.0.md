# ChonkStep 0.4.0 alpha

ChonkStep 0.4.0 adds native screenshots and recording, finger-following desktop
gestures, and reversible workspace layouts. Capture controls have clearer
feedback and keep the cursor visible, while a performance pass reduces overlay
repainting, allocation traffic and unnecessary background work.

## Highlights

- Capture a screen, area or unobscured window as a lossless PNG, or record a
  screen or area to MP4. Screenshots open in the configured image viewer (imv on
  the tested Omarchy installation); completed recordings open in Omacut.
- Select and adjust captures with the keyboard or pointer. The redesigned
  controls retain a visible cursor even after an application hid it.
- Workspace and Overview gestures follow the fingers, reverse naturally and
  settle using release velocity. Drag windows onto desktop thumbnails, or close
  a desktop while preserving its windows on a neighboring desktop.
- Switch among Freeform, Mosaic and Flow workspace layouts, returning to the
  saved floating arrangement when switching back to Freeform.
- Capture queues, GPU readback caches, clipboard admission and helper processes
  have explicit bounds. PNG encoding uses small streaming buffers; cancelled
  screencopy requests no longer strand subsequent requests.
- Closed detail panels stop extra polling and refresh on opening. Application
  indexing, layout calculation, Dock painting and session log discovery do less
  unnecessary work.

## Performance and validation

Repeated nested software-rendered comparisons measured roughly **85–86% less
compositor CPU** while drawing and resizing capture selections, with similar
render counts. Separate allocation profiling measured roughly **69% less
allocation traffic** during selection. An idle selector schedules no periodic
redraws. These are workload-specific results, not whole-desktop speedups.

Qualification includes strict Clippy, documentation, Rust and Python checks;
native capture, cursor, clipboard, screencopy and panel regressions; paired
two-core workloads constrained to 1 GiB and 2 GiB; and a ten-minute stability
run completing 1,813 desktop/capture cycles. The constrained runs had no OOM
events, and the stability checks found no accumulating windows, threads or
non-pipe file descriptors.

Startup and retained idle memory did not improve significantly. Some 2 GiB
pressure checks showed worse input latency despite lower CPU usage; stalls
remain. The tests used nested software rendering on an i9-9900K host and do not
establish physical display latency or hitch-free performance on older hardware.
Native GPU, M1/Asahi and high-resolution 60 fps recording performance still need
hardware qualification. Recording currently uses silent software-encoded H.264.

## Install on Arch or Omarchy

Choose the native `x86_64` or `aarch64` package:

```sh
chonkstep_dir="$(mktemp -d)"
chonkstep_arch="$(uname -m)"
chonkstep_pkg="chonkstep-0.4.0-1-$chonkstep_arch.pkg.tar.zst"
curl -fL -o "$chonkstep_dir/$chonkstep_pkg" \
  "https://github.com/iconidentify/chonkstep/releases/download/preview-v0.4.0/$chonkstep_pkg"
curl -fL -o "$chonkstep_dir/SHA256SUMS" \
  "https://github.com/iconidentify/chonkstep/releases/download/preview-v0.4.0/SHA256SUMS"
(cd "$chonkstep_dir" && sha256sum --ignore-missing --check SHA256SUMS)
sudo pacman -U "$chonkstep_dir/$chonkstep_pkg"
omarchy install desktop-chonkstep
```

The release workflow builds and verifies packages natively for each architecture
and publishes matching debug symbols, `SHA256SUMS`, and GitHub build provenance.
Verify a downloaded package's provenance with:

```sh
gh attestation verify "$chonkstep_dir/$chonkstep_pkg" --repo iconidentify/chonkstep
```
